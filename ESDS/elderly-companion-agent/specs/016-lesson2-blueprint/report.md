## 1. 本次要解决的问题

旧网页实际采用六阶段通用路径：签到、看例子、填三栏、核对、课后安排、结束。它具备基础结构化记录和互动记忆，但没有完整实现老师第二课的作业回顾、三题复习、先表达再对照、两次关系回顾。不能把旧设计文档中的设想当成已有功能。

本次恢复老师教学主线，把不同活动和人物分开保存，保留第一课形成的拒绝处理、同例停问、原话来源、独立记忆及课末复盘。第二课的目标是练习辨认情境、想法和情绪并一起核对可能的联系；填完表、答对提示后的题、结束课程，都不等于已经独立掌握或获得干预效果。

## 2. 逐项前后对照与理论预期

下表“预期”是设计假设，不是实验结果或教师验收结论。

| 环节 | 旧代码行为 | 本次实现 | 预期价值与不能推断的事 |
| --- | --- | --- | --- |
| 签到 | 通用近况入口 | 邀请上周情况，可用1—10分，也可跳过 | 了解当次状态；不能从一个分数推出整周发生了什么 |
| 作业回顾 | 无独立教学子步骤 | 获准的前课安排与本次自述分开；上次已拒绝则不追问是否完成；可跳过 | 为Reflexion提供“尝试、阻碍、需要怎样帮助”的证据，不检查服从 |
| 三题复习 | 无对应运行路径 | 老师原教室场景，逐题判读、反馈，最后汇总原答、帮助及未答 | 发现本次需要怎样讲解；反馈后的后续作答不能标作全程独立测试 |
| 雨天想象 | 泛化示例后直接进入个人记录 | 学习者先表达想象中的情绪和想法；可混合、中性、未知 | 给对照提供自己的观察点，不把情绪分成好坏 |

| 个人三栏 | 通用字段收集；沿用案例会复制旧三栏 | 个人或替代虚构案例独立；前课只沿用情境，当前想法/情绪仍在本课表达 | 避免复制旧答案后误称本课训练完成 |
| 强度与关系 | 无独立情绪评分与图表回顾 | 本人明确0—10；零分保留、越界不截断、混合情绪核对对象；三栏模型与LLM短回顾 | 帮助本人核对；不让模型猜分、强迫因果或承诺情绪改善 |

| 作业与结束 | 通用安排/结束及基础复盘 | 自愿三栏练习、明确结束；固定LLM课末复盘加入活动来源和作业回顾 | 得到下一次教学的待验证建议，不把愿意练习当实际执行 |

原稿措辞调整：第一题从整段判断收束为只判断“他们真是比我聪明多了”，保留原教室、同伴比较与认知考点；强度统一0—10，0表示无强度，解决原稿0—10与最低1分说明的不一致；对未做作业不使用训诫语。原稿没有课末独立考试，本次也没有新增考试或重复第一课整套课程目标。

## 3. 实际程序路径与数据

```text
近况签到 → 作业回顾 → 三题复习/逐题反馈与汇总
 → 雨天：先情绪、后想法 → 小雨教学对照 → 可选感想
 → 个人或替代案例：三栏 + 本人可选强度
 → 三栏模型/LLM短回顾 → 本人核对确认
 → 自愿作业 → 明确结束 → 固定LLM课末Reflexion
```

服务端保留原六个宏观阶段，`lesson2_flow.step` 管理十个可见教学环节。模型建议字段与有限动作，程序校验当前步骤、消息摘录、案例来源、确认和持久化。普通教学JSON先完整校验，正式回复沿用保存后的渐显；不把未校验草稿先流到页面。原HTTP端点、加密状态、幂等、归属和审计继续复用，无新数据库表或迁移。

一次程序运行顺序：网页发送消息和幂等键 → 服务核对归属、版本、revision并先保存用户消息/pending事件 → 加载有效记忆和授权来源 → 候选反馈走一次LLM判读，否则走本课教学JSON → 校验摘录、来源及合法动作 → 更新子步骤，必要时单独生成缓存的案例短回顾 → 同事务加密保存状态/回复/事件记忆和调用审计 → 页面展示正式回复并刷新记录。明确结束后再独立运行课末LLM，失败不能撤销已完成记录；原重试入口和审计继续保留。

主要入口：

- `lesson2_flow.py`：教学子步骤、专用JSON契约、三题、雨天对照、三栏、评分、修改和成果。
- `runtime.py` / `agent.py`：路由到本课教学；共享反馈判读与合法动作，判读失败保留审计并暂停当前询问。
- `boundaries.py` / `memory.py`：独立询问边界与授权摘要；切换案例清空本次收集进度，删除未确认沿用来源时撤回依赖内容和回顾。
- `reflection.py`：课末来源化上下文与结构化假设；保存结果默认 `applied=false`。
- `course.js` / `course.css`：子步骤导航、原答复习记录、来源标注的双人表、三栏模型与可选动作；后续环节把雨天对照折叠保留。

四种证据保持独立：`rain` 是学习者在想象情境中的回答；`contrast` 是预设角色小雨；`draft_record/confirmed_record` 是当前个人或虚构案例，保留 `source_kind/case_id/source_message_id`；`quiz` 保留首次作答、提示与此前反馈。评分不自动传播到其他课程。课间个人摘要沿用既有本人确认、来源版本和使用授权；虚构成果不能被当作个人经历。

## 4. Reflexion怎样使用作业回顾

课堂结构化记录回答“用户本轮实际说了什么、在哪项任务中说、是否有帮助”；Reflexion进一步提出“为什么这次讲法可能不合适、还有什么解释、下一次如何试、怎样核对”。不能把推测升格为用户特征。

例如，用户说：“试着记过，但写到一半就不知道该怎么写。”

- 观察：本人报告一次尝试，并报告书写时遇到困难；引用当前消息。
- 原因假设：自由书写可能缺少起步参照，**待验证**。
- 其他解释：也可能是当时没有精力，不能直接归因于概念不懂。
- 下次建议：先给一个短例子或一栏起步，再邀请本人尝试；不能据此设置永久偏好。
- 核对办法：看新的任务中是否仍需要同类帮助，再修改或撤回建议。

突发反馈由候选规则进入一次LLM判读，普通模型也能报告漏检；明确追问投诉立即停问同例，明确题量拒绝停止剩余复习题。课末则在明确结束后固定调用LLM，统一输出有来源的观察、建议及可选假设（包含其他解释、行动和验证方法）。事件记忆复用独立加密表；课末反思保存在现有加密课程状态，不自动跨课采用。两者不是每轮重复生成整课总结。

课末结构示意（纯模拟，消息ID为占位，不是实际模型结果）：

```json
{
  "observations": [{"text": "本人报告尝试过记录，并在书写时遇到困难。", "source_message_ids": ["示例消息"]}],
  "suggestions": [{"text": "下次可先给一个短例子，再邀请本人尝试一栏。", "source_message_ids": ["示例消息"]}],
  "hypotheses": [{
    "text": "自由书写可能缺少起步参照。",
    "source_message_ids": ["示例消息"],
    "context": "仅针对这次报告的记录任务，不代表稳定能力。",
    "alternative_explanation": "也可能是当时没有精力，或任务说明不够清楚。",
    "next_action": "先示范一栏，再邀请本人选择是否继续。",
    "verification": "观察新任务是否仍需同类帮助，再修订或撤回建议。"
  }]
}
```

外层另保存 `status/attempt/applied=false`；消息来源必须属于本课选定上下文。结构化并不自动保证推测正确，因此“其他解释”和“怎样验证”仍是后续实验重点。

本轮没有自动读取未经额外授权的前课课后日记原文。使用的是获准课堂摘要/课后安排与本课新自述；因此“本人报告尝试”仍不是外部核验的真实执行记录。

## 5. 模拟案例与理论结果（待用户检验）

| 模拟输入 | 设计上应该怎样响应 | 怎样判定设计失败 |
| --- | --- | --- |
| “没做，上次也没想安排” | 记录安排与自述范围，继续复习；复盘不贴能力或服从标签 | 批评、劝说或要求解释没做的原因 |
| “失望，也有点放松” | 保留混合感受，展示另一种教学解释，不逼选正负 | 丢掉一种感受，或把放松判为正确 |
| “想法我上一句已经说了，别一直问” | 停问，保留原事件/已表达内容，未表达项不补造 | 换新故事、重复索取或暗中确认记录 |
| “这次不说自己的事” | 当前拒绝立即生效；只本次范围采用，使用完整虚构材料 | 写成永久禁令、继续问同一私事 |
| “担心大概6分” | 采用当前担心的明确6分，保留原话 | 因格式僵硬拒绝或给其他情绪填6分 |
| “把情绪改为平静” | 保留其他栏，旧情绪强度失效，重新核对/可暂留 | 沿用原分、宣称情绪已改善 |
| “剩下题不做了” | 已答保留，余题标未观察，不计错，不自动完成整课 | 继续问原题或把拒绝当概念错误 |

这些案例预测的是系统行为及体验方向，不预测学习分数提升、Reflexion收益或心理效果；需要后续实际用户试用及专门实验。

## 6. 实际验证与失败记录

离线、真实模型与网页分别报告。离线规则模型只验证工程路径，不作为真实语义能力证据。

工程回归：228项通过（公共40、课程188），日志 `test-results/lesson2-regression-delivery.log`；包括正常路径、混合情绪、零分/越界、原话聚合、同例停问的范围守卫、来源隔离、刷新/重新建Session、幂等、旧版本只读及课末结构化上下文。JavaScript草稿生命周期、保存后渐显、流协议脚本通过；Python与JS语法检查、临时空库Alembic升级到现有head通过。无新迁移。工程测试不证明语义稳定率或学习效果。

收尾来源守卫与对照求助处理调整后，复跑本课18项专项及JS检查通过：另一事件不能混入现有个人案例；对照/感想中的概念求助不被自动推进到个人经历。整例重选尚无新增入口，不把跨故事叙述直接当作替换授权。

真实DeepSeek先后暴露评分长摘录拒绝、投诉仅减少追问、题量反馈误归类，以及同一消息的情绪或近况被拆成重复字段。已修正本课判读指令；明确评分可解析当前情绪的自然前缀，同字段的非评分重复摘录只合并为覆盖各片段的连续原文，保留碎片审计，不改写原话。不同评分不自动合并或选一项。网页另发现“同时表达两栏却只收当前栏”，已移除模型上下文中会强化单栏提问的下一题文本，并加强完整提取指令。失败输出保留，不以成功重跑掩盖失败。

有限真实模型的阶段结果：第三轮完整正常路径、课末复盘、拒绝/本次确认、同例停问、停止剩余题通过（17调用，52,043 tokens，47.803秒）。增加多栏同答检查后，最新整组合成路径中正常路径及课末复盘、拒绝/本次确认、停题、多栏同答通过；同例投诉一例被模型同时输出“回顾当前案例”和“暂停整课”，该轮整体为5/6通过（18调用，55,730 tokens，44.890秒）。程序随后增加动作范围守卫：没有明确整课暂停依据，局部停问不能升级成整课暂停，原模型动作仍保留审计。修复后专项四例（两种雨天同答、个人三栏同答、同例投诉）4/4通过，4调用、10,214 tokens、7.946秒；不能把它改写成“修复后整组重新全通过”。

上述均为少量合成用例；调用和耗时是各组总成本，不是平均每课成本或稳定时延。失败版本与最新原始输出/调用元数据保存在被Git忽略的 `test-results/lesson2-real-blueprint*.json`、`lesson2-extraction*.json`；用 `scripts/check_lesson2_blueprint.py` 与 `scripts/check_lesson2_extraction.py` 可复现，运行真实模型会产生调用费用。网页验证的费用未合并进这些接口合成统计。

累计脚本检查含失败与复验：89次模型调用、254,531 tokens、229.756秒脚本墙钟总和。各轮调用数依次为15、9、17、5、18、18，另有3例及4例提取专项；未额外折算费用，也不能用最终小组耗时代表所有调试成本。

网页验证：第一条正常路径走过签到、作业自述、三题反馈、雨天、个人三栏/评分、关系不确定、确认、拒绝作业与结束。它暴露雨天多栏漏收，已按上述修正。最终版另走过暂不评分、跳过作业回顾、停止剩余题、雨天同轮两栏、跳过感想、个人三栏和评分一次表达、确认、拒绝作业、结束，课末复盘已显示。未作答保留为未观察，记录确认和课后选择分开；按钮消息不再为空，完成后不再显示“请完成本课”的旧阶段提示。刷新保留状态。桌面和390像素移动布局已看图，移动页宽375≤390，无整页横向溢出，三栏在移动端纵排。截图仅在本地 `test-results/lesson2-final.png` 与 `lesson2-mobile.png`。

仍有模型层限制：网页课末建议出现“先给短示范”与“下次不先示范独立核对”并存，需要人工明确教学先后和验证条件；现有结构没有自动证明建议彼此一致，因此保持待验证、不自动采用。后续专项理解测试应覆盖这种复盘内部一致性，不能因JSON合法就判定建议成熟。

## 7. 交付边界

第一课7.1及第三至八课版本、完整教学Prompt不变；共享帮助函数只增加第二课条件分支。旧第二课会话因版本不同保持只读。安全关键词暂停的语境判读/恢复仍按用户要求暂缓，不在本轮修改。未优化token、重构框架、增加新表或上传老师素材。

尚待：用户/教师核对内容与体验；混合情绪和自然语言的更广泛测试；新教学调整是否减少反感与重复、Reflexion是否改善后续指导的比较实验。工程通过不能替代上述验收。

当前第二课新流程实现并验证的是“事件反馈 + 明确结束后的固定复盘”两层；旧 `per_turn/per_task_step/event_driven` 任务Reflector/Actor频率实验尚未接入这些新子步骤，不能据此声称第二课完成了四种频率策略验证。体验服务使用 `--policy none`，仍保留事件反馈和课末复盘；频率实验作为后续架构债务，不在本轮扩展。
