## 旧版 → 新版

| 旧版 | 本次变化 | 作用 |
| --- | --- | --- |
| 暂留事情后直接问下一项 | 明确已暂留哪一项、下一项名称；虚构按钮改为“这一项还分不清／先跳过这一项”，记录为暂未辨认/本人跳过 | 区分个人回忆与案例辨认，不把缺项当答错 |
| 模型回复完成后才清空输入 | 新聊天建立请求快照后立即清空；控制按钮、重试均不清空新草稿 | 发送反馈及时，原消息和幂等键仍能重试 |
| 普通目标消息直接存为目标草稿 | 先一次 LLM 判读 goal/actions/clarify，按当前阶段只提供相关指令 | “完成了”不误记成目标，不推断用户拒绝所有后续安排 |
| 必须逐按钮推进末尾环节 | 同一句明确目标与课后选择，可提出两个有来源动作，在副本上全部校验后采用 | 可直接进入总结，仍保留记录确认、检验和课程结束边界 |
| 右栏作用主要靠用户摸索 | 开场及侧栏说明记录与操作用途，限定可自然推进的环节 | 不承诺任意阶段都能随意跨过 |

## 代码流程

`course.js submit` 捕获不可变请求正文/幂等键 → 清空新聊天草稿 → SSE 请求。失败保留原请求和原消息气泡，同键重试；后续草稿不被重试成功或控制操作清除。

`services` 在目标/课后安排/总结保留 chat 原意，不把全局精确按钮文案提前映射到非法阶段动作。`runtime` 先处理安全和互动边界，再调用 `agent.navigate`。`navigation.py` 定义结构化协议与各阶段 Prompt；每个动作附本轮消息 ID 和逐字引用。程序检查合法阶段、目标草稿、动作顺序及原话来源，再用已有 `_control` 应用整组动作。任何一项失败都不采用部分结果。

最多两个动作；目标阶段可跳过目标+拒绝安排，或确认目标+同意安排。结束课程只允许在本轮开始前已经进入 summary；不能从目标直接结束，不能越过本人记录核对或检验。学习结果、掌握程度和生活中已执行继续分别记录。判读失败记录 `navigation_event=failed` 和调用审计，阶段保持原状，允许重新表达或用按钮继续，不自动隐藏重试。

新第一课版本 `6.7-course-navigation`，旧版只读；新状态含 `navigation_version`。无数据库表变化；既有独立记忆迁移仍须按 011 要求执行。
