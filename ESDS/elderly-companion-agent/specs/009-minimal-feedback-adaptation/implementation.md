# 6.4 最小反馈适配：实现与体验记录

日期：2026-10-18。目的只验证“明确反馈 → 给选择 → 改变当前行为”，不调整八课内容、测试形式、模型温度或反思频率。

## 前后对照

| 项目 | 6.3 | 本次 6.4 | 预期作用 |
| --- | --- | --- | --- |
| 个人练习中的反感反馈 | 沿用普通问答处理，可能继续缺项追问 | 明确整句反馈或“我想少解释一点”入口触发局部适配 | 用户可以直接改变交流方式 |
| 反馈后下一步 | 原当前问题 | “直接看解释／继续聊”两个选择 | 由用户选，不猜测长期偏好 |
| 看解释 | 原来主要按缺项提问 | 当前概念短说明，不追加问题、不编造个人回答 | 允许先理解再决定是否说 |
| 继续聊 | 常规问题加重复引导语 | 当前一个简短问题，后续省去重复引导 | 降低重复负担，效果仍待用户反馈 |
| 结构化记录 | 有个人记录、学习结果及既有反思 | 另存原反馈、来源、原因假设、其他解释、最后选择、局部参数和未测量效果 | 为后续 Reflexion 留下依据 |

这份新记录明确标为 `rule_based_feedback_note`，是最小程序适配记录，不是新增 LLM Reflexion 的结果。深层原因没有在本轮被证实；点击继续也不代表满意。若多次提出反馈，当前状态保留最新记录，历次反馈和选择仍在完整加密消息及 Trace 中。

## 代码流程

1. `practice_flow.feedback_action()` 只识别少量明确整句；不把“很烦”、事件中的别人、转述或否定自动解释成不喜欢 Agent。按钮提供不依赖整句匹配的入口。
2. 现有服务先持久化本人消息，运行时完成安全/暂停检查后执行反馈操作；反馈和按钮均零模型调用，不触发四要素摘录和澄清计数。
3. `practice_flow.control()` 保存一份局部记录：反馈原话/来源、待核对原因和其他解释、选择及来源、`reply_length=short` 与 `follow_up=offer_choice/one_question`，`effect` 始终为 `not_measured`。
4. `course_payload()` 和 `_context()` 提供有效 `interaction_adaptation`；前端复用个人练习的按钮区。`reply()` 与 `update()` 落实程序可控的解释出口和短提问，不只靠 Prompt 自觉执行。用户直接回答也可继续，不强制多点一次按钮。
5. 当前案例的个人练习结束后，适配不再进入 Agent 输入；修改重开会清除本次适配，不自动扩展到独立测试或跨课摘要。核对仍完整展示本人原话，不为简短而截断。
6. `learning_check.report()` 留下反馈记录；独立课后复盘额外保留反馈与最后选择的消息来源，即使已超出最近 40 条。既有 Reflector/Actor 调用策略不变，无隐藏模型调用。
