# 评测API配置来源修复

2026-10-23，R-010的评测前置修复。用户发现评测费用记入旧API账户；随后明确要求以后以模块`ESDS/elderly-companion-agent/.env`为准。

## 已核对的原因与限制

当前进程已有DEEPSEEK_API_KEY，且与模块.env不同。run_dialogue_eval先load_dotenv（默认不覆盖），再调用从进程环境取key的客户端，因此更新文件不能保证评测用新凭据。--provider原默认deepseek还会覆盖文件中的提供商选择。历史manifest记录提供商/模型而不记录凭据来源，不能仅凭模型名认定扣费账户。

本轮只比较是否相同，不输出密钥/前后缀/散列；不再调用模型。当前冲突支持配置优先级的原因判断，但历史请求没有保存可验证的账户身份，不能冒充已从运行目录追溯出确切账户。023/024/025的输出和usage仍是真实记录；正确API账户基线身份暂不采纳，不删除原始证据或静默重采。

## 最小变更

- 只修评测入口，不改产品客户端、.env内容、常驻服务、课程Prompt/版本或数据库。
- 默认从明确的模块.env解析API配置；--env-file可显式指定其他文件。该文件是本评测进程的API配置权威，不回退到继承密钥/模型/endpoint。
- --provider保留为文件配置一致性断言，省略时取文件值；不再默认覆盖文件。缺密钥/模型/部署或来源不明确时在创建客户端之前失败。
- 只覆盖客户端使用的API选择变量，不把整个.env加载到进程；Azure等可选API变量在文件缺失时也不沿用旧继承值。拒绝相关配置的环境插值，避免间接继承旧密钥。
- manifest仅记录配置文件路径、来源、提供商和发生冲突的变量名，不记录密钥及其指纹。
- 用户确认以后可用新源，不等于授权本轮再消费。仅离线验证；真实重采需另列预算。

## 验证

用临时虚构配置测试文件覆盖旧进程变量、缺失不回退、提供商不匹配与插值拒绝；默认离线起点仍0调用。实际配置检查只给来源/相同与否等事实。完整隔离回归，不发送模型请求，不读取真实用户数据库。
