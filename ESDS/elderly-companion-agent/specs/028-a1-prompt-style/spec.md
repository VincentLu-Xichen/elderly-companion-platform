## 3. 整体Prompt核对后的判断

| 当前位置 | 实际行为/约束 | 对首切片的意义 |
| --- | --- | --- |
| `prompt.py:prompt_for_lesson`第一课分支 | 通用主Prompt＋第一课规则＋Schema一次发送 | 可以在统一主Prompt内调整表达风格，不必增加Agent或调用 |
| `COMMON_PROMPT`开头 | 已有平等交流、回应原话、两三句口语/30—80字、不哄人等要求 | 问题不是完全没写风格；可检验更具体的风格描述是否有用 |
| `lesson_1.py:SYSTEM_PROMPT` | 明确摘录、当前目标/评分对象、教学阶段和自然回应；含历史兼容说明 | 整体存在可审阅的优先级/重复要求，首轮不一起清理，以免改变推进含义 |
| 第一课`runtime._teach`＋`dialogue.enabled` | 当前learn/practice/review普通教学在对应分支恢复`decision.reply`；评分无效、停问/安全等仍可纠正 | 主Prompt风格有机会到达展示端；必须逐轮检查，不能只统计代码中有多少reply赋值就判全部被覆盖 |
| 第二课`prompt_for_lesson`＋`lesson2_flow.PROMPT` | 使用独立主Prompt/Schema，未拼入第一课COMMON_PROMPT；reply只承接，程序追加问题或在部分节点替换 | 只改COMMON_PROMPT不会改变第二课；两课同时改会扩大切片，第二课稍后单独处理 |
| 目标导航/判题/回顾/课末反思 | 各有职责与Prompt | 不用主Prompt风格优化声称已改善这些独立调用 |

**建议：整体检查，局部替换。** A1-1先只检验第一课主Prompt中的沟通风格段。之后根据证据决定是否处理其他指令冲突、输出覆盖或动作限制；不一次重写整份Prompt并同时调参数。

## 4. 最小切片卡

| 项目 | A1-1提议 |
| --- | --- |
| 问题 | 用户希望语气有人情味；现有风格要求较概括，实际旧E01有较长复述。需要验证更具体的语言风格要求是否改善普通教学表达 |
| 候选方法 | 在第一课统一主Prompt内替换一段沟通风格要求，不新增推理步骤、示例库或额外模型调用 |

| 唯一主要变量 | 沟通风格指令包的措辞；不能把包内某一句的独立作用从本次整体比较中推出来 |
| 预期 | 自然、温和、有分寸；回应具体内容，解释和问题衔接顺畅，减少流程播报、机械复述和固定安慰开头 |
| 禁止 | 以温暖为由代判心理、亲昵哄劝、保证好转、编造事实、强迫积极、代确认或无视拒绝；课程材料和必要教学不删 |
| 保持 | 模型、temperature=1.0、thinking关闭、tokens上限、历史/上下文、Schema、合法动作、案例、最终组合规则及辅助/事件/课末机制 |
| 验证 | 先静态范围核对/必要回归；未来同条件成对采集A参考与A1-1，原始JSON、最终回复和状态分开比较，人工理由与程序事实分开 |
| 调用上限 | 本轮0。未来建议初探配对总上限12次尝试，每版最多6次，含辅助/失败，不重试；这是待明确执行的建议，不是本轮调用授权 |

首轮保留普通回复“两三句、约30—80汉字”和“每轮只问一个具体问题”的原措辞、原语义；不同时放宽篇幅、改提问时机或更改课堂动作。若这些限制实际妨碍自然表达，另记证据后独立试验，不能偷偷纳入A1-1。

## 5. 可直接审阅的替换段（未应用）

**只替换COMMON_PROMPT中的原风格段：**

```text
与学习者平等交流，听见重点，回应原话，每轮只问一个具体问题。普通回复用两三句连贯口语，约30—80汉字；不堆术语、不哄人、不替本人作决定。
```

**候选A1-1风格段：**

```text
与学习者平等交流，语气温和、自然、真诚，保持成年人与成年人交流的分寸。用熟悉的日常中文表达关心、解释和邀请，让人容易听懂，也愿意接着说。
回应本轮原话中值得回应的具体内容。简单答复可以直接承接；有困惑或感受时贴合原话回应，不必每轮复述整份记录或加一句泛泛安慰。开头、句式和衔接随语境自然变化，避免像播报流程或给表现写评语。
每轮只问一个具体问题。普通回复用两三句连贯口语，约30—80汉字；不堆术语、不哄人、不替本人作决定。表达关心时保持有依据和有分寸，不擅自断言对方的内心，不用亲昵称呼、夸张称赞或好转承诺替代具体回应。
```

此段是具体设计，不是经过试验的“最佳Prompt”。没有复制N1/E01的用户台词、参考回复、分支判据或隐藏人物事实；首轮不加入few-shot，避免同时测试示例效果和风格文字效果。不能把候选段写进现有运行文件而不记录版本差异。

## 6. 保留的问题与失败解释

- E03跨案例混写/返回来源拒绝有程序与模型两部分原因，A1-1不修改控制器，不能宣称风格Prompt会修复它；这个阻塞继续影响整体基座验收及进入B的条件。
- E04复合确认受当前动作/程序路径限制，语气优化不能证明修复确认。E06-b由独立导航及固定参考材料组合产生的问题也保留。
- 第二课程序追加的固定问题可能仍影响整体自然度；本片不改第二课，不能以第一课结果外推两课。
- 风格文字变长会增加输入，可能使模型更啰嗦、共情套路化或影响同次JSON的摘录/动作。因此要检查全部输出和状态，不只评价reply。新旧长度与实际tokens/等待照记，不能预先声称省费。
- 若模型原话改善但最终展示没改善，归入组合/覆盖问题，留作单独切片；若两边都没有可解释改善，调整或放弃这段风格要求，不能仅因写得更长就保留。
