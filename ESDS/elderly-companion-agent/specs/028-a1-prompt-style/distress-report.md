## 原因定位：不是API失败，也不是普通回复覆盖

1. 评测入口从指定模块`.env`读取配置，不回退继承的旧凭据。两次均返回deepseek-flash、finish_reason=stop、完整JSON和usage；未改配置文件。
2. 两版使用028归档的完整主Prompt，指纹分别为`e8e815fa…b08b16`与`6a064abb…564b2`，未根据新场景再改风格。共同初始历史、首轮输入、模型参数相同，初始状态只差课程版本元数据；候选只传入隔离评测Agent，不改产品文件。
3. `FreeformCourseAgent`把JSON解析为TeachingDecision成功。当前Schema允许摘录列表；主Prompt说明每轮最多4条，没有明确写每个字段只能一条。因此本次不是“模型JSON无法解析”，而是模型输出形状与后端额外约束没有对齐。
4. `runtime._apply_observations`验证本轮原话来源，遇到第二个behavior时抛错，整个`process`未返回TurnResult；不是先得到好回复再被模板替换。输入状态保留原四项、评分为空、未确认、未完成。
5. 使用保存的两份原始JSON分别离线回放，0新增API请求，均复现同一异常。再仅在诊断副本移除第二条behavior时，摘录校验可通过。这只定位重复字段阻塞；丢弃内容并不是本轮实现或验证过的修复，也没有据此伪造后续回复。

网页流式失败分类的源码将该异常映射为`duplicate_evidence_field`；本轮没有启动网站或验证页面/SSE呈现，不能以后台片段声称真实页面体验已跑通。强烈难过本身没有被本地危险关键词规则暂停；这不证明系统能全面判别安全风险。
