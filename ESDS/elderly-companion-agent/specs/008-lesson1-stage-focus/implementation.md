# 6.3 实现、前后对照与验证

日期：2026-10-16。范围：第 1 课。第 2—8 课版本和教学流程不变。用户同意以“明确每阶段重点、有边界地练习、允许真实缺失”的方向修订。

## 改了什么，带来什么

| 位置 | 原 6.2 行为 | 6.3 行为 | 目的及实际边界 |
| --- | --- | --- | --- |
| 阶段呈现 | 阶段名、部分过渡语 | 九阶段持续显示任务、目的、继续条件；补练有独立提示 | 用户能看见当下练什么，不需要理解内部状态机 |
| 个人练习 | 模型决定自然语言追问，四项有原话才结束 | 程序选择当前项、一次澄清、暂留或核对；模型仍负责识别本轮原话 | 限制追问范围，不由模型自拟念头和身体反应推动对话 |
| 暂时没有内容 | Prompt 允许不确定，程序缺少字段级出口 | 本人选择“暂时想不起”“先不谈”；两次回答仍未获得当前项时记“本次暂未整理清楚” | 区分选择与未观察，次数不作为能力、重要性或质量评分 |
| 核对与修改 | 四项必须有原话 | 四项各有原话或暂留说明即可核对；修改会重开暂留项 | 避免为了通过流程填造内容；关键确认仍由本人操作 |
| 结构化结果 | 个人练习通常用通用完成表述 | 完整、部分、未观察三个范围，独立保留缺失原因与消息来源 | 流程完成不再暗示完整个人应用或已经掌握 |
| 课间与复盘 | 摘要要求四项齐全 | 仅沿用实际存在的原话，摘要附缺失范围；复盘保留暂留来源 | 后续指导能知道哪些信息没有获得，不把缺失变成心理特征 |
| 流式展示 | none 策略下教学草稿可流出 | 第 1 课个人练习不流出模型/Actor 草稿，完整校验后展示程序回复 | 保证当前环节的提问边界；其他支持流式的环节沿用原机制 |

## 从代码到程序行为

1. `catalog.py` 将第 1 课升为 `6.3-learning-check`。`new_course_state()` 初始化 `practice_flow`，与原 `draft_record` 分开。
2. `practice_flow.py` 的 `FOCUS` 配置九阶段教学方向。`course_payload()` 暴露 `stage_focus`，页面随已提交的阶段更新，不由模型宣布阶段完成。
3. 进入个人练习时，`current_field()` 只选尚无原话且尚未暂留的一项。`_context()` 同时给模型本课目标、当前项和已有记录；第 1 课 Prompt 明确不深挖事故原因、不替用户提供内容。
4. 普通回答仍调用一次教学模型，经 Pydantic、字段白名单、最新来源与精确摘录校验后才写入。`update()` 接收已验证字段，保留跨项回答；当前项初问和一次澄清后仍缺少内容，就保存独立 `not_observed` 说明，转下一项。
5. 两个暂留按钮走既有带 CSRF、归属、幂等键和 revision 的接口，零模型调用。`not_recalled`、`withheld` 与自动暂留的 `not_observed` 均只保存状态和来源 ID，不写进 `draft_record`。
6. `ready()` 允许“原话或暂留”覆盖四项后进入核对。`confirm_record` 保存原话、缺失状态及 `practice_scope`，然后原 `learning_check.begin()` 进入独立案例 A 四题。修改会撤销旧确认与派生成果，重新开放暂留项。
7. 完成时 `learning_result`、artifact 包含本人确认的快照和真实范围。`memory._summary()` 只授权当前版本、本人已确认且同归属的成果；不存在的原话不会被复制。`reflection.py` 即使选最近 40 条，也额外保留所需暂留来源；复盘仍不改本人记录、不自动用于下一课。

例如，“就很吓人啊”在本次真实体验中被识别为心情；用户再次这样回答时，当前缺少的想法被暂留，随后转问做法。记录保留原话，不补成“会不会撞到人”，也不从中判断用户能力。

课内策略仍是 none/per_turn/per_task_step/event_driven。触发时原 Reflector/Actor 调用边界保持，一轮最多原来的三次；个人练习中 Actor 生成文本不越过程序当前任务，不作为最终显示回复。频率与教学收益仍待实验。

- 隔离完整回归：**122 项通过（公共 40、课程 82）**，日志：`test-results/lesson1-stage-focus-regression.log`。

- 复盘来源测试特意把暂留原消息挤出最近 40 条，验证仍提供来源，生成复盘后不改本人记录。全部暂留走完整九阶段时，个人应用仍为未观察，四题跳过仍为未观察。
- Python compileall、JavaScript 语法、前端 SSE 协议 6 项和 `git diff --check` 通过；换行提示不是校验错误。无数据库表变更，无迁移。
- 真实 DeepSeek 网页用合成案例验证：示例辨认 → 个人事件 → “就很吓人啊” → 一次澄清后再次同样回答 → 自动暂留想法并转问做法 → 本人先不谈 → 核对；刷新恢复、修改重开、两种按钮及带缺项确认进入案例 A 第一题均已验证。
- 网页验收发现两个新按钮的乐观消息文字缺失，已补齐标签并重新加载、点击验证。
- 当前真实网页停在案例 A 第 1 题，留给用户继续体验。本次未提交该题到真实模型，未重做整课真实模型复盘；完整缺项路径和复盘来源由隔离测试验证，不能据此声称教学效果已证实。
