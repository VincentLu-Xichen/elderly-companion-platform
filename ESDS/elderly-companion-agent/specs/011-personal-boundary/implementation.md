2026-10-18。状态：实现与工程检查完成，等待用户体验验收。第 1 课升级为 `6.6-personal-boundary`；其余课程不升版，只读取已确认边界。完整目标见 [spec.md](spec.md)。

## 相比旧版改变了什么

| 旧版行为 | 本次行为 | 预期作用 |
| --- | --- | --- |
| 整体拒绝容易进入单项未答计数，接着问同一私事的其他部分 | 候选规则只触发 LLM 判读；整体拒绝立即停止该案例，独立处理单项拒绝、否定、转述与暂停 | 尊重拒绝且不将其记为答错 |
| 互动记忆主要是少追问、短回复参数 | 独立 `personal_disclosure` 类型，明确区分事件反思与确认后的询问约束 | 不把隐私边界压缩成表达风格，也不被风格更新挤掉 |
| 练习回复被固定程序文案覆盖 | 第 1 课新版共同练习保留模型回复，程序只负责合法状态、来源与保存 | 允许承接原话，而非机械逐项索取 |
| 换案例后可能混用已有字段和个人成果 | 新案例 ID、独立材料、清空活动进度、历史归档；字段和成果均有来源类型 | 虚构辨认结果不冒充个人经历 |
| 后课默认仍邀请个人经历 | 每轮检索有效边界；新课创建时就调整开场和案例来源 | 避免每课重新确认同一偏好 |

不改独立检验题目；未进行整课精简、课末协议重写、频率实验或 token 优化。

## 代码与程序流程

1. `services.process_course_turn` 先保存用户消息及 pending 审计，加载同参与者的风格记忆和询问边界。
2. `boundaries.candidate` 是高召回入口；命中或存在待确认时，由 `agent.reflect_interaction` 使用专用结构化判读。普通教学也可报告漏掉的拒绝；已有主判读时不允许第二次覆盖。
3. `boundaries.apply` 验证意图和范围，立即停止当前个人追问。第一次整体拒绝自然确认一次；模糊或不回应只按本次处理，确认不是继续门槛。已明确说“以后都不要问”直接采用。
4. `switch` 为新材料分配案例 ID，归档旧记录、清空活动字段。LLM 承接并提问；`runtime` 校验摘录、来源和阶段。界面显示“案例练习”，待确认时不显示逐项按钮。
5. `interaction_memory.save_memory` 与回复、状态、审计同事务保存。确认记录引用原拒绝和确认回复；检索重新核对两条来源、归属、存活和原文。单独按类别检索，风格最多三条不影响边界。
6. 后课读取有效 `do_not_solicit` 默认用虚构材料。明确撤回才解除；仅授权本次私事不会解除跨课限制。虚构结果不进入个人经历摘要；课末总结带明确来源声明。

判读失败留下失败审计，停止当前敏感追问，允许稍后继续，不创建长期禁令。观察、原因假设、其他解释和实际调整分开；内部反思不显示为对话。
