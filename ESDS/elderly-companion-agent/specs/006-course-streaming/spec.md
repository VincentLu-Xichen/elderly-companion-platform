# CBT 真实模型与流式回复

日期：2026-10-16。依据：用户要求前端逐步显示回答，并接入 LLM。原版课程后端已有百炼/Azure 客户端，但网页一次返回完整 JSON；隔离体验脚本强制使用离线规则。

## 场景与边界

学习者在现有八课页面发送消息，模型产生回复时逐步阅读，完成后看到由服务端校验的课程记录。用户补充只有 DeepSeek API，新增 `deepseek` provider，默认模型采用官方当前文档的 `deepseek-flash`，可配置覆盖；现有百炼与 Azure 保留。缺少密钥时明确报错，禁止自动伪装为真实 LLM。离线规则模式仍可显式选用。

## 协议与不变量

- 新增 POST `.../messages/stream`，鉴权、CSRF、归属、同意、长度与速率限制与现有接口一致，原 JSON 接口保留。
- SSE 事件包含开始、回复片段、成功结果或错误；成功结果采用原接口响应结构，持久化完成后才发送。
- 只投影顶层 `reply` 字符串，正确处理任意分块及 JSON 转义，不流出结构化字段、判读或反思过程。片段是生成中的临时内容，最终由服务端合法阶段和回复约束收口，可能被替换。
- 完整 JSON/Pydantic、原话来源和阶段校验通过后才保存状态。失败撤下临时回复并保留原幂等键重试；没有终止成功事件不得当作成功。
- 可能触发课内反思时不预先展示教学草稿，只允许最终 Actor 的回复流出；判题与 Reflector 结果不流出。确定性按钮一次返回，无打字延时伪装。
- 独立工作线程拥有独立数据库会话。浏览器断开后已经开始的请求可继续校验与持久化，刷新读取结果，同键重试可回放，禁止无限缓冲。
- 模型密钥仅在服务端从环境读取。隔离体验新增真实 provider 选项，仍使用临时数据库、随机应用密钥、仅监听回环地址，不改正式数据。
- 本轮不改变教学目标或判据；真实 DeepSeek 测试发现检验 Prompt 缺少明确的 JSON 指令，现补齐，故第 1 课升级 `6.1-learning-check`，其余课程版本不变。DeepSeek 适配层把历史消息封装为 `course_history` 输入数据，包含每条消息的 id/role/content，避免模型将历史 assistant 的 `{id,text}` 当成输出模板；来源 ID 和原始存储不变，适配协议记录为 `deepseek-course-json-v1`。反思频率仍待实验。

## 验收

验证真实流式片段在模型结束前产生、JSON 解码边界、结构字段不泄露、失败不推进、成功后幂等回放、断连恢复、接口权限；执行公共与课程回归以及 JS 语法检查。在有可用密钥时，以虚构回答验证真实模型与网页；无密钥如实报告未完成的实测，不编造连接成功。
