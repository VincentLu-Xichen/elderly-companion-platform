## 原来、改动与作用

| 原行为 | 本次改动 | 作用与限制 |
| --- | --- | --- |
| 核对四要素后直接选课后安排 | 原六阶段扩为九阶段，增加四题检验、回看补练、本人目标 | 分开引导整理与减少帮助后的辨认；进度不表示掌握 |
| 只有简短示例，原版四题未完整保留 | 先明确解释四要素，再用 A 新案例逐题辨认事情、想法、心情、做法 | 四题结束后统一反馈，减少前题答案提示；仍是项目自编题，未做测量效度验证 |
| 记录完整即可形成成果 | 独立保存回答、任务、来源、判读、提示和帮助标记 | 学习结果不依赖模型回忆，跳过记为未观察，实际生活使用仍未知 |
| 没有明确补练记录 | 反馈后可选 B 新案例两题，分别检查想法与心情 | 不覆盖首次回答；只有一组补练，不代表所有薄弱处都获得充分训练 |
| 没有独立学习目标确认 | 先收一项目标原话，可修改、确认或跳过 | 供后续内容设计参考；目标数量和评分等继续体验讨论 |
| 课后复盘主要为短观察与建议 | 输入本课学习结果、已确认记录、目标及来源消息，增加结构化情境假设 | 包含其他解释、下一步和核对办法；尚未自动用于后课，也没有证明个体化收益 |
| 旧记录可能与新流程混淆 | 只提升第 1 课版本，旧第 1 课只读，其他课不升级 | 不静默迁移或把已见案例当作陌生案例；本课编辑后重答标记已有接触 |

原版最早可见提交 `c385b4b` 有四题、目标及日记；本次恢复这些功能，并改为统一反馈及分开记录补练。原版相信程度与情绪强度尚未恢复，明确作为待办，不归入程序重构。近况评分依然可跳过。

## 前端体验步骤

在模块根目录启动：

```powershell
.venv\Scripts\python.exe -B scripts\run_course_preview.py --port 8000 --policy none
```

打开 `http://localhost:8000/`，邀请码 `course-preview`。这是隔离临时数据库的离线规则体验，不调用真实模型；页面有明确标识，正式环境不提供检验示例答案。

1. 登录、阅读记录告知、进入 CBT 目录，选择第 1 课。
2. 点击“先看例子，不评分”；示范问题回答“这是想法”。
3. 个人练习可用虚构输入：“事情：朋友没有回消息；想法：他是不是不愿理我；心情：失落；做法：没有再联系”。也可逐项回答，或用“填入一条体验示例”填入当前阶段示例后发送。
4. 核对右侧记录，点击“确认这份记录”。
5. 四题可依次回答：“邻居走过来向他问好”“他会不会觉得我没礼貌”“紧张”“低下头，没有回应”。想查看错误分支，可把第三题答成“低下头”。提示和跳过均有按钮。
6. 完成后查看统一反馈。选择“换个例子再练一次”，两题可回答“我今天的安排全乱了”“失望”；首次与补练分别展开查看。
7. 点击“继续，设置练习目标”，输入一项希望练习的方向，核对后“确认这个目标”，或暂不设置。
8. 选择课后安排，可说一句本课反馈，再点击“完成本课”。右侧显示检验结果、目标和课后教学复盘；反思不改写本人记录。

## 程序与代码连接

```text
course.js 提交 action/content/revision/idempotency_key
  → router.py 验证请求，services.py 校验归属、版本、串行与幂等
  → runtime.py 按当前阶段分流
      教学阶段 → agent.py 教学 JSON → 摘录与合法阶段校验
      本人核对 → learning_check.begin → A 案例第 1 题
      检验回答 → agent.evaluate_answer → CheckAnswerDecision
                 → 最新消息来源校验 → 保存程序取得的回答原文
      四题结束 → learning_result → 统一反馈
      可选补练 → 独立 retry 记录 → 保留首次表现
      目标草稿 → 本人确认或跳过 → 课后安排 → 显式完成
  → services.py 保存加密状态与审计，返回 course_payload
  → course.js 显示案例卡、当前题、检验记录和目标
  → 完成后 reflection.py 独立后台复盘，失败可重试
```

`learning_check.py` 管题目、提示、状态、结果投影；`schemas.py` 定义判读及假设的结构；`prompt.py` 分开教学、检验判读、课后复盘的任务；`agent.py` 仅执行模型调用。检验判读只有 verdict/reason/source_message_id，不负责对话或阶段跳转。课程阶段和本人确认由程序控制。

普通教学调用保持原机制；检验判读每次最多一次、450 tokens，不叠加课内 Reflector/Actor。概念提示、重读、跳过、目标草稿与确认不调用模型。课后独立复盘第 1 课最多 1200 tokens，其余课 600。复盘选取最近 40 条及检验/个人记录的来源消息，避免首题依据因对话变长而被截掉；校验返回来源，不要求输出思维链。

结构化学习结果保存本次任务表现；结构化 Reflexion 保存基于证据的解释假设，两者都是结构化数据。四题检验在完成时汇总结果，主要反思在完成本课后生成，此时已包含检验、补练、目标和本人反馈。逐轮、子任务或事件触发的额外反思仍是后续实验变量；本次体验显式关闭额外课内反思，不把回答时长或精神状态作为重要性评分。

失败处理沿用加密、审计、幂等与串行机制。判读超时或来源错误不推进题目；同键重试与成功请求回放不重复写入回答。复盘失败不撤销课程完成与检验结果。客户端使用文本节点呈现答案和假设。
