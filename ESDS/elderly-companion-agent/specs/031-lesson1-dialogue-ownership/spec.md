# 031 第一课六项交流要求落地

2026-10-26，R-010。用户明确要求实施其圈出的六项行为要求，并制作按板块解释的修改总结；不只修最近串读的三个技术点。

## 需求与边界

| ID | 用户要求 | 本次可核对行为 |
| --- | --- | --- |
| R1 | LLM结合上下文决定返回邀请，可早于10轮 | 当前教学调用可提出邀请；不增加固定轮数门槛或额外判断调用 |
| R2 | 正常回复及引导措辞由LLM组织 | 普通教学、导航及已有判题反馈保留模型表达；程序只执行已校验动作，不无条件拼接下一问；固定任务起始材料、显式按钮回执、错误和安全保护保留 |
| R3 | 篇幅按需要，不强制30—80字或每轮提问 | 放宽统一风格篇幅建议；保持现有输出token与合法结构上限；提问以必要和低负担为准，可零问 |
| R4 | 落实用户已认可、可扩展的六种交流情况 | 正常学习、概念思考、伤心倾诉、表达结束后的邀请、持续交流、暂不返回分别有表达与状态支持 |
| R5 | 简短贴合回应也可以完成一轮 | 非作答轮不因没有新字段或问句而消耗回答机会、自动暂留或推进 |
| R6 | 邀请返回与用户同意返回分开 | 邀请只保存返回点，不直接恢复教学；带本轮依据的继续意愿才恢复；不同话题不混入原案例 |

第一课四要素、评分、练习、目标和自愿课后环节保留，不据四个字段齐全提前结束。第二课6.2、Daily Chat、前端、模型参数、数据库结构及.env不改。既有辅助职责保留，不新增判断层；自然语言检验求助改用原判题调用生成回应（部分短语原先为0调用），显式帮助按钮仍0调用，报告此调用变化。已有来源、用户隔离、本人确认、安全、幂等与加密守卫保留。正常模型回复不是不经合法性校验就展示。不得自动提交、重启、追加付费请求。

## 协议与程序职责

- 普通教学仍使用统一主Prompt。增加本轮有来源的交流意图：作答、概念问题、继续交流、邀请返回、暂不返回、同意恢复。意图是局部教学动作，不是心理事实、永久偏好或课末Reflexion。
- 模型上下文提供结构化待办、评分对象及量尺，不给普通教学一整句必须执行的next_question。原固定问题生成器保留用于明确材料、按钮及旧协议。
- 临时交流保存原阶段／case_id及邀请状态，原记录和评分继续沿原加密状态保存。邀请不切阶段、不确认记录；恢复须核对当前案例／阶段与返回点及最新用户依据。
- 概念问题、倾诉、侧话题及返回邀请不计未回答。明确尝试回答但仍缺当前项时保留原有限澄清／暂留；新事实仍经现有逐字来源守卫。
- learning_request与互动反馈兼容同一交流状态。没有新的心理推断调用，没有固定10／20轮循环。
- 兼容旧合成输出：已校验的confusion信号且无字段摘录可以解释为概念问题，须标明兼容来源；其余旧输出沿原作答路径。不能把旧JSON回放当成新Prompt的真实生成效果。

## 验收

逐项离线验证六项需求、邀请／拒绝／主动继续、保存并重开后的返回点、正常评分及0分、非作答不耗次、不同案例不混写、错误来源／否定／转述／非法组合拒绝、普通模型回复原样保留及旧课只读。完成全模块回归、语法和必要合成数据库集成；用已有真实JSON回放定位计数变化，不增加真实调用。

交付须包含：修改板块→旧行为→新行为→代码位置→验证与限制；与本轮开始源码快照对比的逐文件差异；具体Git保存清单。工程完成仍标质量Validating，真实模型和用户体验未知。
