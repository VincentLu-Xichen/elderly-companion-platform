## A基线是什么

当前同一个教学Agent负责普通教学，没有新增主管或任务Agent。每课有自己的主Prompt，动态传当前状态、已有材料及来源化历史；程序校验来源、合法动作、本人确认、保存与审计。原有互动判断、目标导航、判题、案例回顾、课末Reflexion独立存在，不能将全系统描述成只有一个Prompt或每轮只有一次请求。

实际入口核对：第一课agent.reply接收prompt_for_lesson，第二课agent.lesson2_turn真正使用lesson2_flow.PROMPT＋Decision Schema＋最后摘录提醒；rain时还有既有专项提醒。因此“统一主Prompt”是主指令体系，不是所有状态字节相同。保留这些既有设计，避免删掉能力后制造弱A。本轮5类实际Prompt和每次请求参数/哈希见[基线契约](baseline-contract.v1.json)，原Prompt全文另存原始运行目录prompts/，没有复制密钥或真实用户数据。

程序的固定材料和回执也是A整体行为的一部分。A0不是对裸模型的能力测量，也不是B/C架构优劣结论。

## 一组请求说明模型与程序的分工

E04第2轮的预设输入：

> 记录准确，可以继续。

真实模型JSON返回 `advance=false, observations=[], practice_origin=current_case`，reply为：

> 谢谢您核对，记录就按您说的保留；“当时做了什么”没谈到，就先空着。右侧模型里，想法、担心和做法之间的联系，不用现在下结论，您看过觉得有哪里想改或想补，再说就好。

最终展示保留这段话，但状态仍review、未确认。定位源码可见 `dialogue.confirms_record` 只接受一组完整精确确认表达，该复合句未匹配；之后进入普通教学，而此教学Schema无confirm_record动作，advance不负责review本人确认。这是**自然确认入口/动作契约限制**，不能只凭模型客气回应就说“确认成功”，也不能只加主管后声称模型变聪明。模型未主动澄清/提出合法替代也是可审阅的互动表现，但本轮不修该缺口或改变动作集合。

对照E07：模型reply原话解释比较不代表心态评分；程序随后将contrast推进rain_insight，保留reply再追加固定回看邀请；无个人摘录，confirmed_record=null。本例说明回复和状态都要看：保留解释有价值，但不是完成、掌握或本人确认。

按一次实际执行理解架构：运行器构造合成起点和历史 → runtime处理合法状态/现有事件入口 → 单教学Agent或原专用辅助方法生成JSON → Schema与来源校验 → 程序更新允许状态并组合展示 → 记录原始JSON、最终回复、状态和调用轨迹。网页另有持久化加密/幂等层，本次运行不写产品数据库；不能用此局部采集代替网站、刷新或跨课验证。
