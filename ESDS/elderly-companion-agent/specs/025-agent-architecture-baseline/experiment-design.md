## 先明确要证明什么

共同问题：在保留老师前两课主线、自然承接、本人确认和来源约束的前提下，哪种组织方式能更可靠地完成对话任务，额外代价是否值得？

不把“多Agent”“少tokens”“模型更大”本身当成果。以下命题都可被否定：

| 方案 | 可检验假设 | 可能失败的原因 |
| --- | --- | --- |
| A 每课统一教学主Prompt | 一个教学Agent加现有辅助机制，足以完成目前若干普通和异常交互 | 主指令互相干扰、上下文缺漏、程序覆盖、动作不支持；必须分别归因 |
| B 主管协调任务Agent | 主管保持原任务/来源，让任务Agent专注局部内容，可减少忘记原事和承接/收束冲突 | 交接丢失、主管误路由、同质模型重复错误、最终汇总再覆盖好回复；成本变高 |
| C 单Agent按任务装配Prompt | 不增加核心调用，用更聚焦的任务指令减少无关要求干扰，同时保持连贯 | 分块过窄、误路由、遗漏通用边界或反复开场；长历史仍可能造成干扰 |
| D 固定选定架构再比较模型/参数 | 某些任务可由成本更低或延迟更小的模型完成而无关键质量退步 | 结构化失败、重试/升级回大模型抵消收益；小模型不一定在实际部署更快 |

## 顺序与公平比较

1. **A0现在：** 冻结024后实际代码/Prompt/案例，原6例8轮完整局部组，最多12请求取得描述性初步输出，不宣称架构胜负。
2. **B下一候选：** 先构造可审阅的主管/任务Agent协议，离线和同JSON回放，之后才在独立预算内A对B。A固定不动，不能先修A的动作限制再把收益记给B。
3. **C随后候选：** 从同一个A派生，A对C；不直接把B改成C。这样能区分主管协调方案和Prompt聚焦方案各自的贡献。
4. 初步改善才做有限交错重复及事先冻结的新表达；之后按两张整课卡在隔离会话体验。局部固定输入无法代替自发回归教学、持久化与整课覆盖。
5. 根据质量和总代价选A/B/C或决定局部混合；混合须作为独立方案，不把B+C同时加入的效果归给其中之一。
6. **D最后：** 固定架构/Prompt先换模型；再固定模型逐项改推理设置、输出上限等。模型更换与参数调整分别报告，禁止同轮缩上下文、换模型、换架构。

B/C中相同数据必须获得相同来源标注、语义起点、材料、最近历史和确认权限；每种方案只看到实际对话，不能看到case.checks/human_review、完整体验卡或隐藏人物事实。模型端版本/日期不可锁定时记录服务返回标识和时间，旧A0只能作历史基线；正式A/B在相近时间重采A、交错顺序，不能把跨时段差异全归架构。

## B实验卡：一个主管保持目标，任务Agent按需协助

**目标切片：** 先选E01-a（已表达内容整理）、E03-a（暂聊/明确返回）和E07-a（比较中的承接），共3例4轮。它们能查理解和连贯；E04复合确认若被程序动作门挡住，不是增加主管就能解决的证据。E06-b目标导航属于原有专用调用，不适合拿来证明普通教学主Prompt分块有效。二者仍作为全组已知缺陷/后续保护案例。

**如何起作用：** 同一个主管保存本轮任务目标、活动case_id、来源和待完成内容；它决定直接回应或委派一个教学任务Agent（初版最多一个任务Agent）。任务Agent只返回局部解释/回应草稿与来源化建议。需要委派时由主管整合最终reply及候选字段/动作，交给现有程序校验。只有主管对用户形成最终回复，任务Agent不自行推进、确认或写用户记忆。

**有界接口草案（未实现）：**

- 输入：lesson/task/current_case、当前状态及原始来源化历史、本人本轮话、合法字段/动作、有效互动指导。
- 主管决策：direct/delegate、task_type、必须保留的事实引用、当前应停问/暂停的边界、未解决任务；只给简短可核对理由，不要求或保存模型私密思维链。
- 任务输出：reply_draft、source_message_ids、candidate_observations、uncertainties；引用原始消息，不能把主管摘要当用户新事实。
- 最终输出：与A同一教学Decision Schema；所有原有白名单、来源、权限和完成门禁保持。不能用“主管说可以”替代本人确认。
- 直接路径最多1次核心调用；委派路径最多3次（主管判断→任务Agent→主管整合），不循环重试或自我辩论。失败即记录，不能偷偷回退再调用A并漏计。

**唯一主要变化：** 教学协调架构包（主管/委派/整合及必要角色Prompt）。角色Prompt随交接机制一起变化，因此只能说测试B整体，不能声称单独证明“多一个Agent”有效；本轮所有角色仍用A同一模型/参数，辅助机制照旧。

**前置拦截：** 若A的最终程序覆盖使两种原始reply均不可见，先冻结问题并单独修/再建基线；若合法动作集合根本不支持目标意图，先记录契约缺口，不靠放宽校验让B通过。024的E07修复已包含在A。

**建议未来烟雾预算（本轮不执行）：** 同3例4轮，A上限8、B上限16次，配对合计24次尝试，含全部辅助/失败；最多每版本1遍。达到上限停止，不追加漂亮样本。金额及每个角色输出上限在实现前再核实；重复/整课预算另列，不默认获准。

**保留判据：** 至少一个预先指定的问题有原话与状态支持的改善，原成功的关键行为未退步；所有来源/确认/边界硬约束通过，记录新增调用、等待、tokens。若只有同义改写或没有改善证据，暂不升级；若新增严重混事、越权或忽略停问，拒绝该版。样本少时写“初步可继续/证据不足”，不宣称统计优越。

## C实验卡：一个教学Agent，按任务选择指令块

**目标与起点：** 同B的3例4轮，仍分别对A，不继承B改动。按当前服务器教学任务装配“共享课程/边界块＋当前任务块”，初版不加LLM路由器。

**如何起作用：** 在第一课整理/解释和第二课对照等普通教学入口，为当前任务突出对应指令；共享课程目标与规则始终存在。仍由同一个教学Agent一次输出，不把每个分块变成一个新Agent或串行多次调用。用户暂聊时，任务块须允许承接，并保留原任务；不能由分块硬编码每次扳回。

**控制变量：** 模型、温度、输出Schema、历史窗口、状态上下文、素材、合法动作、辅助机制及最终展示组合均与A相同；只变主Prompt装配范围。首轮不同时删历史、压缩上下文、增加新材料或加主管。记录每个任务块及实际装配Prompt哈希，未知任务走预先声明的A主Prompt回退（一次调用，显式记回退，不先试失败再付费调用）。

当前A本身已有分课、目标导航等专用Prompt，第二课普通教学也有rain状态提醒。C须逐项列“原有/保留/新拆分/替换”，不能把已有提醒包装成新方法，或把A说成全系统一个Prompt；若目标任务本来已经充分聚焦而无冲突证据，允许C不进入付费试验。

**建议未来烟雾预算（本轮不执行）：** A8、C8，配对最多16尝试，含辅助/失败。相同模型下不能因C较短就提前认定便宜；记录实际输入/输出、失败、等待和缓存明细可得性。Prompt tokens变少是此机制可能结果，质量须同时比较。

**判据：** 同B的质量/硬约束要求，另查是否遗漏通用边界或反复重开场。若任务拆分后只是长Prompt换成多个同样冗余的片段，或效果相当但维护/路由更复杂，保留A；不为已经设计过分块而必须采用。

## 评测记录：避免把流程限制当模型能力

逐轮读取：预设输入 → 实际请求/上下文 → 模型JSON → 校验及动作 → 最终展示 → 保存状态。每个问题可有多种原因：

| 类别 | 需要的证据 | 能否直接归因架构 |
| --- | --- | --- |
| 模型理解/教学 | 正确上下文下原始reply/intent/摘录错误 | 只是候选解释，仍需同条件A/B |
| 上下文缺失 | 关键历史/已表达字段实际没传入或来源混乱 | 不能只改Prompt后声称模型更聪明 |
| 程序覆盖 | 原始reply有效而最终展示被替换 | 先修展示责任，不先换主管 |
| 状态/动作限制 | 模型建议合理但当前合法动作不接收 | 架构保持同动作集合时无法证明修复它 |
| 接口/环境 | HTTP/连接/超时/结构化失败，有明确轨迹 | 与教学体验分开计，但失败成本计入总账 |

程序硬约束逐项通过/失败；对理解承接、自然展开/收束、教学方向分别给更好/相当/更差/无法判断及原话，不合成一个“智能分”。人工评价可打乱A/B展示顺序，但现阶段Coding Agent审阅不冒充用户或盲评。

指标统一记录：每轮与每case总调用（按主管/任务/教学/辅助拆分）、输入/输出/总tokens、失败/重试/回退、完整等待；支持流式才另外记首个正式可见回复延迟。多角色总等待包括全部串行步骤，不把任务Agent局部耗时当用户等待。费用逐请求有可核实价格/缓存才算，否则unknown。若少于足够重复，不报告有代表性的P95；完整时间分布与样本数一起给出。

本地8轮只能看有限路径；E03由用户明确返回，不能当Agent主动择机收束的证据；E06-a是0调用程序确认，不是LLM理解成功；课末/跨课/刷新必须另走集成/整课。两课完成也不代表学会或干预有效。

## D与新效率方法：后置候选，先量质量

模型参数量、推理开关、temperature、最大输出长度是不同维度。闭源未公开参数量标未知，不用模型名字推断；较小参数模型的实际速度受硬件、服务排队、网络、输入长度和批处理影响，必须同部署条件实测。模型路由先有单模型对照；计算全部路由、重试、升级调用后的每个合格完成案例总成本，不能只拿小模型标价当节省。

其他方法归I-012/I-009候选池，暂不编码或切换服务：

| 方法 | 适用条件/最小试法 | 风险与本轮状态 |
| --- | --- | --- |
| 稳定前缀缓存 | 主Prompt/静态教学材料重复，提供商有可核实缓存支持；单独比较冷/热缓存 | 不一定减少逻辑tokens；缓存命中、写入费用、TTL未知不能算收益。当前客户端未保存缓存细项，仅候选 |
| 上下文按来源选择 | 长会话中相同记录反复发送；保持来源/否定/案例边界对照全历史与选取上下文 | 压缩丢事实和权限可能伤理解；另一个主要变量，不能与C同时做 |
| 低置信升级模型 | 已有小/大模型任务质量证据，定义可观测升级门控 | 模型自信不等于正确，门控错误及多次调用可能更贵；待D单模型比较 |
| 反思频率/门控 | 经现有I-009规则设计独立实验 | 不能为了少tokens取消必要理解或课末固定Reflexion，本轮策略不动 |
