2026-10-23，R-010，关联I-005/I-010/I-011/I-012。用户要求先收束当前单Agent/单Prompt设计并用已有数据取得初步输出，再设计主管多Agent、任务分块Prompt，后续才进入模型/参数及效率优化。用户已明确选择“每课统一教学Prompt，保留辅助机制”。

## 本轮交付与授权边界

本轮冻结并采集A基线、写出B/C/D实验方案。当前产品实现不做功能重构、不改Prompt、模型、参数、课程版本或用户数据库。024仍待用户体验，其已知E04/E06-b等问题随基线保留，不为让基线漂亮先修。研究顺序已确认，不等于B/C/D全部编码及付费运行获准；候选有具体方案后按范围推进。R-010仍唯一目标。

## A的可核对定义

A = 单一教学Agent承担当课普通教学 + 每课固定主Prompt + 动态状态/历史 + 现有程序守卫 + 原有独立辅助调用。

“单Prompt”指**普通教学入口不按任务新增路由Prompt**，不是全系统只存在一个字符串或每条消息必有且仅有一次LLM请求。第一课教学经agent.reply使用prompt_for_lesson；第二课实际经agent.lesson2_turn使用lesson2_flow.PROMPT加Decision Schema，不能把构造Agent时传入的第二课SYSTEM_PROMPT误当作实际教学请求。第一课目标导航、两课判题、互动判断、自然回顾及课末Reflexion仍可能使用专用Prompt，逐请求计入总成本。确定确认等程序路径可为0调用；这些既有调用不等于新主管多Agent已实现。

本轮课程为第一课7.5-two-lesson-backend／第二课6.2-contrast-reply；deepseek现有配置、temperature=1.0、thinking disabled、非流式；任务反思none，事件互动Reflexion启用。课末独立LLM继续，但局部案例不结束课程，本轮不声称验证课末/跨课。

源码补充：第二课lesson2_turn在主Prompt与Schema后已有“完整摘录所有allowed_fields”提醒，rain步还会追加一段专项示例。因此A准确名称是“单教学Agent／每课统一主Prompt体系（含现有状态提醒）”，并非每步发送字节完全一致的字符串；本轮不删除旧提醒来制造更弱基线。C比较的是进一步按教学任务组织指令的增量价值，不声称此前从未分块。

## 本轮采集卡 A0

- 问题：现有A在统一合成输入下实际怎样回应、怎样推进、哪里仍失败？本次无A/B优劣假设。
- 数据：原cases.v1.json，cbt12-local/1，6例8轮；不改起点/输入/评分。原始人物与标准只留评测端，教学模型只见实际消息、状态与材料。
- 冻结：实际Git状态、源代码zip/指纹、案例副本、模型参数、Prompt清单/哈希、语义起点；不能只引用旧HEAD。023/024均保留，不覆盖旧输出。
- 运行：先离线起点检查，再**一次**真实完整局部组，上限12次实际请求，含辅助与失败；不自动重试。使用已有运行器，不换模型/密钥、不起服务。
- 预算：最多12尝试、单请求上限不超过现有1200输出tokens，理论输出总上限14,400 tokens；输入与失败消费按实测，无法预先核实的金额保留未知。不再额外做重复/裁判/模拟用户付费调用。预算用完则保存已取得证据停止。
- 证据：所有逻辑请求、原始JSON、最终展示、前后状态/trace、错误/缺usage、调用/tokens/完整等待；非流式无首字指标。程序检查和Coding Agent人工审阅分别报告。
- 交付：基线结果表、失败定位、B/C实验卡及成本取舍、下一步建议，不把一次采集称为用户验收或整课有效。
