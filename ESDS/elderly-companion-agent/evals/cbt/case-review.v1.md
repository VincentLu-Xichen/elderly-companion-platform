### 突发状况：补充方向已认可，按含义和上下文组织

用户认为上述补充有价值，希望Agent能应对更多突发状况。后续整理应覆盖“不知道、纠正、拒绝、否定确认、暂聊、概念困惑、计划与实际”等不同问题，重点核对Agent是否理解含义并采取合适动作，而非增加一批关键词规则。同一句“先不说”需结合当前对象；单项拒绝、本次拒绝和长期边界仍须分例，不能互相替代。

最小整理方式是每个候选先写清前文、当前任务、用户改变了什么及应保留什么；无需穷举所有意外。调试所用表达与后续未参与修改的变体分开，避免只适应固定句子。价值是提高覆盖的解释力；风险是案例无限扩张，因此仍只围绕前两课当前问题分批收束。

### 生活情境与口语：Prompt指导和样本覆盖分别承担职责

用户提出可在后期Prompt设计中说明生活化情境。Agent建议：Prompt可要求理解用户自己的生活事件、采用易懂表达，减少对考试示例的依赖；但这不能代替实际用其他情境检查。大范围扩充可后置，样本设计阶段先列出少量同一语义问题的家庭/邻里/活动等变体，并另列零碎口语变体。后续比较时尽量分别改变情境或表达方式，避免无法判断差异原因。

以上是建议，不把所有生活情境塞进Prompt，也不在本轮新增执行数据。具体选哪些生活事件仍可随人工审阅补充，不据此改变课程主线。

### E01自然路径候选：先讲述，再由Agent邀请评分

用户希望评分由Agent引导；可在前面简要说明，缺评分时礼貌返回当前任务。核对现有实现：第一课已有两种分别询问的0—10分量尺，分别针对想法相信程度、情绪强度，并允许暂不评分；不应与第二课开头本周心情量尺混用。此处调整首先是测试路径的真实性，不是立即修改评分教学。

以下均为**待讨论的输入/交互示意，不是已运行对话或模型实测输出**：

1. **开始说明（候选）：** “稍后我们可能用0到10分，描述您当时多相信某个想法、情绪有多强；到那一步我会分别说明，也可以暂不评分。”不因前面提过就认定用户已经理解。
2. **用户自然讲述（候选输入）：** “昨天数学考试最后一道题没做出来。我就觉得别人肯定都会，只有我不会，心里很担心，考完还一直翻答案。”保留原事件与四要素，先不主动给分。
3. **Agent按实际阶段邀请（候选行为）：** 先承接、采用已提供内容；需要评分时，明确引用“别人肯定都会，只有我不会”，单独询问当时多相信，说明0分与10分含义及可暂不评分。情绪强度另在合适位置询问，不把两种分数混在一起。
4. **用户后续分支：** 根据实际提问作答，分别检查下表情形，不把所有分支串成同一个人反复为难Agent的剧本。

| 候选分支 | 示例用户原话 | 合理行为边界 |
| --- | --- | --- |
| 明确给分 | “这个想法当时我信八分。”；另例“零分” | 依据当前明确评分对象记录；0分与未提供不同，不推断另一项分数 |
| 继续谈感受、没有给分 | “我就是一直惦记着，越想越烦。” | 先回应新增内容，适时礼貌回到刚才的评分对象；不把漏答直接当拒绝或错误 |
| 不理解或难以估计 | “什么叫相信几分？”；另例“这个我真说不好。” | 针对量尺或困难给简短帮助，有限澄清；仍说不清可暂留，不替用户猜分 |
| 明确暂不评分 | “这项先不打分。” | 尊重本项选择，不重复催问，不扩大为永久拒绝所有评分 |
| 明确停问或暂停 | “别再问了，我想先停一下。” | 尊重停问/暂停，不能因开头已介绍评分而继续追问 |

“礼貌拉回”的候选含义是承接后提醒当前任务，并区分未答、不会答与拒绝；不以每轮都得到数字为验收目标。现有第一课规格已限制追问次数，本候选不增加次数。正式转成案例前须补齐每条评分邀请的前文与状态；原E01及027结果保持原样，新路径使用新版本/独立案例，不冒称与旧单轮起点完全相同。

## 人工最有价值的参与方式

1. 标注原话是否像真实用户，会不会过于整齐、刻意刁难或前提不清。
2. 补充生活中的表达和事件类型，不必从零设计技术结构。
3. 判断什么回应让人愿意继续，哪些追问造成负担；允许多种合理回复，不定唯一标准台词。
4. 用户/教师判断教学主线；Coding Agent负责把意见整理为可执行的起点、独立分支、来源和验证条件。

后续顺序：审阅原样本 → 人工补充/修改 → 确定合理行为边界 → 保存新案例版本 → 有界测试和基座优化 → 用未参与修改的表达检查是否只记住固定样本。当前原始样本和旧输出保留，不自动进入下一步。
